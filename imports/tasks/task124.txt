ksystemlog: использование polkit для повышения привилегий
Описание
В данный момент утилита KSystemLog запускается через kdesu (в ярлыке галка для этого стоит, вроде бы X-KDE-SubstituteUID), то есть спрашивает именно пароль от "root", а не от юзеров в группе wheel.

В Росе с помощью патча это переделано с kdesu на pkexec, чтобы была возможность запустить программу с повышенными привилегиями на тех компьютерах, где root отключен, но есть пользователи в группе wheel.

#104

https://abf.io/import/ksystemlog/pull_requests/1

При этом, сама программа может работать и без админских прав, но тогда будет ограниченный доступ к журналам.

Постановка задачи
Необходимо реализовать механизм повышения привилегий через polkit для тех операций, которые требуют права администратора, при этом чтобы сама программа работала от обычного пользователя.

Среди KDE приложений есть те, которые так умеют, которые можно посмотреть для примера. Судя по всему, таким приложением является Диспетчер разделов от KDE.

Скорее всего, для этого необходимо реализовать D-Bus службу (helper), которая будет получать необходимые данные с повышенными правами (с помощью polkit), например, содержимое системных журналов, и отправлять эти данные в интерфейс.

В самом интерфейсе скорее всего должен быть какой-то переключатель программы в привилегированный режим, по нажатию на которую появится окно ввода пароль в polkit, после чего в программе станут доступны к чтению те журналы, которые были изначально недоступны для обычного пользователя.

Суть привилегированного режима в том, чтобы не запрашивать права администратора на каждую попытку чтения такого журнала, а только один раз на эту сессию работы программы (и / или до момента, пока пользователь не переключится обратно в обычный непривилегированный режим по нажатию на переключатель).

Также такой переход в привилегированный режим можно осуществлять не только по нажатию на этот переключатель, но и при первой попытке обращения к журналу, требующего права администратора.
