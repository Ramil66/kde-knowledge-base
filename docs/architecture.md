# Архитектура и план MVP

SQLite принадлежит одному локальному пользователю. Несколько запусков CLI могут работать с одним файлом. Хранилище выбирается через `--database` или `KDE_KB_DATABASE`. По умолчанию файл находится в каталоге данных пользователя по XDG.

| Модуль | Ответственность |
| --- | --- |
| `cli` | Команды Typer, ввод с терминала и из stdin, отображение результатов через Rich |
| `schemas` | Проверка полей структурированного импорта с помощью Pydantic |
| `models` | Реляционная модель SQLAlchemy, внешние ключи и индексы |
| `database`, `migrations` | Подключение, транзакции, версии схемы и резервное копирование |
| `services` | Создание, чтение, изменение и удаление записей, разрешение ссылок и связи |
| `importers` | Разбор документов, сохранение оригинала и привязка к сущностям |
| `retrieval` | Полнотекстовые запросы к FTS5 |
| `exporters` | Экспорт всех прикладных таблиц в JSON в одной транзакции чтения |

## Путь данных

Команда импорта передаёт исходный текст и формат сервису в одной транзакции SQLite. Сервис сохраняет оригинал с SHA-256, проверяет структурированные поля, находит или создаёт сущность и связывает её с оригиналом. Триггеры обновляют FTS5 в той же транзакции. Поиск возвращает тип, идентификатор и фрагмент текста. Оригиналы и комментарии считаются пользовательскими данными. Их содержимое не исполняется.

## Последовательность реализации

1. Создать пакет, схему, первую миграцию и команды обслуживания файла БД.
2. Добавить сервисы и CLI для репозиториев, задач, веток и MR.
3. Добавить транзакционный импорт, отдельное хранение исходных документов и ручное связывание.
4. Добавить FTS5, экспорт и резервную копию.
5. Проверить чистую установку, повторный импорт, внешние ключи, поиск после правок, экспорт и восстановление копии.

Для второго этапа добавить `architecture_notes`, `decision_records` и правила ревью с внешними ключами на документы и комментарии этого этапа. Для заметок и решений хранить ревизию кода и дату проверки. Для правил отдельно моделировать статус подтверждения, область действия, авторов и противоречащие источники. Расширять поисковый индекс отдельной миграцией после добавления этих таблиц.

## Проверяемое извлечение

`importers.preserve_document` сохраняет оригинал в отдельной транзакции. `extraction.inspect_document` получает ответ через `LLMProvider` вне транзакции записи, проверяет схему и наличие в оригинале ключевых идентификаторов, ссылок и дат, затем сохраняет предложение. `extraction.confirm_document` повторно проверяет предложение, разрешает ссылки и применяет его через общий сервис `store` в одной транзакции. При конфликте откатываются также вложенные записи. Выбор Ollama или совместимого сервера и параметры транспорта находятся в `providers`. Базовые операции каталога работают при отключённом провайдере.
